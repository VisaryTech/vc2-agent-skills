# Локальное извлечение PDF с контролем качества

## Окружение и запуск

Пути команд отсчитываются от каталога скилла. Используй отдельное окружение Python 3.11/3.12, CPU; не изменяй зависимости чужого проекта.

```bash
python -m venv /tmp/pdf-markdown-venv
/tmp/pdf-markdown-venv/bin/python -m pip install -r scripts/requirements.txt
```

Windows: `py -3.12 -m venv <venv>`, затем `<venv>/Scripts/python.exe`. Для текстового слоя, рендеринга и вырезок достаточно PyMuPDF; PaddleOCR импортируется лениво. Pillow нужен для контрастирования и поворота повторных OCR-вырезок.

```bash
python scripts/pdf_to_markdown.py extract document.pdf --out /tmp/document-md
python scripts/pdf_to_markdown.py extract document.pdf --out /tmp/document-md --pages 1-3,7
python scripts/pdf_to_markdown.py extract document.pdf --out /tmp/document-md --pages 7 --refresh
python scripts/pdf_to_markdown.py extract document.pdf --out /tmp/document-md --fail-on-quality
python scripts/pdf_to_markdown.py render document.pdf --page 7 --out /tmp/page-7.png
python scripts/pdf_to_markdown.py crop document.pdf --page 7 --bbox 100,200,400,350 \
  --out /tmp/document-md/assets/page-0007-formula-01.png
python scripts/pdf_to_markdown.py review /tmp/review.json --out /tmp/document-md
```

- `--pages`: физические страницы с 1, диапазоны/списки без дублей, в порядке оригинала. По умолчанию все страницы; некорректный диапазон отклоняется до обработки. Выборочный запуск обновляет эти страницы, сохраняя остальные страницы рабочего документа того же PDF.
- `--ocr auto|always|never`, по умолчанию `auto`. В `auto` OCR запускается по признакам качества текстового слоя или наличию растровых областей. `always` запускает OCR каждой выбранной страницы. В обоих режимах текстовый слой сохраняется и объединяется с OCR по координатам; разночтения остаются альтернативами. `never` сохраняет явные предупреждения, если OCR нужен.
- `--dpi 300`: исходный рендеринг. `--threads 8`: потоки CPU. `--refresh` создаёт новую версию извлечения выбранных страниц, сохраняя историю и журнал исправлений.
- `--lang ru,en` и `ru` выбирают `PP-OCRv5_mobile_det` / `cyrillic_PP-OCRv5_mobile_rec`. Для других языков используй один код PaddleOCR, например `en`; произвольные списки языков не поддерживаются.
- `--det-model-dir` / `--rec-model-dir`: каталоги совместимых локальных моделей. При передаче обоих каталогов отключается предварительная проверка источников моделей через `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True`, если переменная ещё не задана. Без каталогов PaddleOCR может скачать модели при первом запуске.
- `render` и `crop` создают PNG. `crop` по умолчанию использует 600 dpi. `--bbox x0,y0,x1,y1` — **пункты PDF (72 на дюйм), неповёрнутая страница, начало слева сверху**. Используй координаты из кэша; пиксели требуют пересчёта. Поворот страницы учитывается, выход за границы отклоняется.

## Контроль качества и ограниченные повторы

Профиль `quality.PROFILE` и его версия входят в ключ кэша. Проверяются количество и плотность текста, состав Unicode-символов, повреждённые/служебные символы, повторение строк/последовательностей, перекрывающиеся дубли и растровые области. Короткий заголовок, число или формула сами по себе не являются ошибкой. Измерения находятся в `native_quality.metrics`, причины — в `quality_flags` с координатами и подробностями. Это эвристики; отсутствие флагов не означает полной проверки.

После OCR отмечаются пустой ответ, confidence ниже 0.85, повреждённые символы, разночтения и изображения без распознанного текста. Для проблемных областей выполняются максимум две дополнительные попытки: вырезка при повышенном разрешении (450–600 dpi), затем автоконтрастирование и поворот на 90° против часовой стрелки. Крупные области разбиваются на вырезки, чтобы движок не уменьшал мелкие символы до лимита 4000 пикселей. Максимум восемь областей на страницу; остальные явно отмечаются `retry_region_limit`. Ошибка загрузки/исполнения OCR не вызывает одинаковых повторов всей страницы. Сохраняющиеся сомнения и исчерпание попыток передаются визуальной сверке. Высокий confidence повторной попытки не удаляет противоречащие исходные варианты.

Каждая попытка сохраняет PNG-вход и его SHA-256, параметры, матрицу перехода в координаты PDF (для вырезок), ответ движка до преобразования, извлечённые строки и ошибку. Сырая информация не заменяется исправленным текстом. Нативные блоки сохраняют строки, span-ы, шрифты и координаты; таблицы — исходные строки и геометрию ячеек. Растровые изображения и векторная графика сохраняются вырезками без выдуманного описания. Для векторов сохраняются команды рисования и общая область; `vector_content_unverified` предупреждает о графике и возможных буквах в контурах.

Элементы `elements` содержат `id`, `pdf_page`, `bbox`, `type`, `reading_order`, `links`, `provenance`, `alternatives`, `fingerprint`. Типы/связи имеют статус `provisional`. ID основан на странице, типе и геометрии; fingerprint дополнительно учитывает содержимое. Текст не нормализуется и числа не преобразуются в float. Точные дубли с перекрытием объединяют происхождение; разночтения не исправляются автоматически. Порядок учитывает колонки и заголовки; сложная вёрстка может потребовать визуальной коррекции.

Неуверенные формулы и кандидаты таблиц сопровождаются PNG-вырезками. Сетка таблицы автоматически не объявляется проверенной: Markdown сохраняет текстовые кандидаты и изображение. Подтверждённую таблицу/формулу регистрируй как исправленный Markdown через `review`, охватив все заменяемые элементы, включая текстовые фрагменты внутри таблицы.

## Выход, состояния и продолжение

```text
DIR/
  document.md                  # итог: автоматическое извлечение + действующие исправления
  assets/                      # переносимые оригиналы сомнительных страниц и вырезки
  .work/
    manifest.json              # текущий запуск и накопленный документ
    draft.md                   # автоматический результат без исправлений
    reviews.json               # отдельный журнал всех ревизий визуальной сверки
    history/<run>.json         # предыдущие манифесты
    cache/<key>.json           # указатель/копия последней версии для переиспользования
    cache/<key>/<run>.json     # версия извлечения страницы
    attempts/<key>/<run>/      # PNG и JSON каждой OCR-попытки
    pages/page-*.png           # оригиналы для просмотра
```

Скрипт создаёт итоговый `.md` и пересобирает его после `extract` и `review`. Исправления вноси через журнал: ручные изменения итогового файла при пересборке будут заменены. Итог и `assets/` переносимы вместе; для повторной обработки и аудита сохраняй также PDF и `.work/`. Не запускай несколько процессов с одним выходным каталогом.

Состояния независимы:

| Поле | Значение |
| --- | --- |
| `execution_status` | `running`/`pending`, `completed`, `partial`, `error`: только выполнение |
| `quality_flags` | признаки подозрительного результата с областью и причиной; пустой список не доказывает полноту |
| `review_status` | `pending`, `partial`, `verified`, `stale`: фактическая визуальная сверка |

`status`, `complete`, `processed_pages`, `partial_pages` сохранены для совместимости. `complete` и эти списки относятся к **текущим выбранным страницам**, а не доказательству качества. `document_pages`, `available_pages`, `error_pages` описывают накопленный документ. `pages` содержит состояние каждой накопленной страницы. `reviews` показывает применимость записей журнала. Проверка отдельных элементов даёт partial даже при отсутствии других элементов: она не доказывает полноту всей страницы.

Коды: `0` — вычисления выбранных страниц завершены; `2` — некорректные аргументы/вход, ошибка или частичное выполнение; `3` — вычисления завершены, но при `--fail-on-quality` остались признаки качества в накопленном документе. Визуально подтверждённое противоречие или неразборчивое место остаётся флагом независимо от verified.

После прерывания повтори команду. Кэш переиспользуется только при успешном выполнении и совпадении версии схемы, SHA-256 PDF, страницы, профиля, языка, DPI, потоков, версий движков и моделей. Ошибочные/частичные страницы повторяются; сомнения качества не мешают переиспользовать завершённые попытки. Повреждённый кэш пересчитывается. Запись файлов атомарная; прерванный запуск оставляет pending для ещё не пройденных страниц и `complete: false`. Новая схема не использует старый кэш, старые файлы остаются на диске.

Явные каталоги моделей хешируются по содержимому. Для стандартных автоматически выбранных ru/en-моделей фиксируются файлы в `$PADDLE_PDX_CACHE_HOME/official_models` (по умолчанию `~/.paddlex/official_models`). Для других конфигураций и отсутствующих файлов выставляется `model_fingerprint_unavailable`: точное воспроизведение весов не подтверждено. Передача обоих локальных каталогов устраняет эту неопределённость. После первой загрузки моделей следующий запуск может получить новый ключ кэша из-за появления отпечатков. Это не гарантия побитового детерминизма OCR на разных процессорах; сохраняются исходные данные и параметры для повторения.

Зашифрованный PDF нужно предварительно разблокировать. Ошибки отдельных страниц не останавливают остальные. Ни OCR, ни эвристики не гарантируют распознавание любого документа; ограничения должны оставаться видимыми.

## Регистрация визуальной сверки

Прочитай элементы выбранной страницы в кэше и просмотри оригинал/вырезки. Подготовь JSON (реальные хеши, ID, координаты, original и evidence возьми из результата):

```json
{
  "source_sha256": "<SHA-256 PDF из манифеста>",
  "reviews": [
    {
      "pdf_page": 7,
      "scope": "elements",
      "element_ids": ["<ID элемента>"],
      "bbox": [100, 200, 400, 350],
      "original": "0,029l м³",
      "corrected": "0,0291 м³",
      "result": "recognition_error",
      "basis": "На увеличенной вырезке последний знак числа уверенно читается как 1.",
      "evidence": ["assets/page-0007-formula-01.png"]
    }
  ]
}
```

- `scope: elements` проверяет перечисленные элементы. `scope: page` допустим только после полной сверки страницы, включая потенциально пропущенные области: нужны все ID страницы и bbox всей страницы. Даже страницу без элементов нельзя объявлять проверенной автоматически.
- `original` — точные автоматические тексты элементов в порядке `element_ids`, соединённые `\n\n`. Для таблицы-кандидата её собственный `text` пуст; распознанные значения находятся в `rows` и дочерних текстовых элементах. Включай дочерние элементы при замене всей таблицы. `corrected` заменяет группу одним Markdown-фрагментом в позиции первого ID; порядок ID определяет размещение исправления.
- `result`: `confirmed` — совпадение; `recognition_error` — ошибка извлечения с обязательным `corrected`; `source_contradiction` — противоречие оригинала без изменения содержания; `unreadable` — оригинал нельзя уверенно прочитать. Для confirmed/source_contradiction `corrected` — null или точный original. Для unreadable допустим null либо фрагмент с явной отметкой неразборчивости.
- `basis` — обязательное основание фактической визуальной сверки. `evidence` — непустой список относительных путей к просмотренным PNG внутри DIR (включая `.work/pages/...`). Наличие файла не доказывает, что он был просмотрен: за истинность записи отвечает агент/проверяющий.
- Журнал хранит хеш PDF, страницу, ID/координаты, исходное и исправленное содержание, fingerprint, SHA-256 просмотренных изображений, время и основание. Неверный PDF, несовпадающий original, неизвестные ID, неверная область и отсутствующее изображение отклоняются до изменения журнала.
- Повторная регистрация той же группы создаёт новую ревизию, предыдущая остаётся superseded. Полная сверка страницы заменяет все прежние проверки этой страницы. При изменении ID/границ группы передай необязательный `supersedes: ["<ID прежней проверки>"]`; ссылки разрешены только в пределах той же страницы и PDF. При изменении исходных элементов запись становится stale: исправление не применяется, но остаётся в журнале и замечаниях Markdown. Зарегистрируй новую проверку по актуальному извлечению. Журналы других PDF хранятся, но не применяются.

Скрипт технически регистрирует утверждение о сверке; визуальную работу выполняет агент. При обычной конвертации агент автоматически проверяет отмеченные проблемные области. Полная сверка всего документа — по запросу.

## Проверки разработки

```bash
python -m unittest discover -s tests -v
```

Тесты требуют PyMuPDF, numpy и Pillow; PaddleOCR подменяется в сценариях ошибок, повторов и геометрии. Реальный OCR проверяет `tests/test_real_ocr.py`: установи `PDF_MARKDOWN_REAL_OCR=1`, `PDF_MARKDOWN_DET_MODEL` и `PDF_MARKDOWN_REC_MODEL` в пути локальных моделей и запусти тот же unittest. Без флага этот интеграционный тест пропускается. Он создаёт синтетический скан и проверяет точное извлечение тестового значения и сохранение сырого ответа. Не добавляй документы заказчика, веса, кэши и журналы в репозиторий.

Пакет `scripts/pdf_markdown/` переносится вместе с точкой входа `scripts/pdf_to_markdown.py`. Модули: `document` — PDF/рендеринг; `quality` — профиль и измерения; `ocr`/`retries` — движок и попытки; `structure` — элементы/порядок; `cache` — хранение и отпечатки; `extraction` — координация; `review` — журнал/публикация; `draft` — Markdown; `cli` — команды.
