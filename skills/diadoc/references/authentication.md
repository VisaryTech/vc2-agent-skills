# Авторизация Диадока

Документация проверена 19.10.2026. Клиент проверен автономно; реальные обращения к API не выполнялись.

CLI получает access token через Refresh Token Flow и передаёт его как `Authorization: Bearer <access_token>`. Токен хранится только в памяти процесса и обновляется перед очередным запросом за 60 секунд до истечения `expires_in`. Дискового кэша и автоматических повторов запросов нет.

## Получение токена администратором

1. Подготовь техническую учётную запись с доступом к нужным ящикам; для черновиков нужны права создания и редактирования.
2. Если приложения нет, [подключи API](https://www.diadoc.ru/integrations/api). В [Кабинете интегратора](https://integrations.kontur.ru/) получи `client_id` и выпусти API-ключ `client_secret`.
3. Установи `clientMode=AuthorizationCode`. В разделе «Выпуск токенов» выбери `openid`, `profile`, `email`, `offline_access`, `Diadoc.PublicAPI`.
4. Нажми «Получить refresh-токен», войди технической учётной записью, подтверди доступ и введи API-ключ. Сохрани выданный `refresh_token`.
5. Укажи параметры приложения и refresh token в настройках CLI ниже. CLI выполняет следующий обмен самостоятельно, без заголовка Authorization:

```http
POST https://identity.kontur.ru/connect/token
Content-Type: application/x-www-form-urlencoded
```

| Поле | Значение |
|---|---|
| `grant_type` | `refresh_token` |
| `client_id` | ID приложения |
| `client_secret` | API-ключ приложения |
| `refresh_token` | Полученный refresh token |

Используй refresh token, выпущенный в Кабинете интегратора для Refresh Token Flow. Если ответ содержит обновлённый refresh token, CLI использует его до завершения процесса, но не перезаписывает env-файл. Сохранение ротируемых токенов между запусками для других способов авторизации не поддерживается. Недействующий refresh token выпусти заново в кабинете. Срок его действия ограничен: по документации, обмен нужен не реже раза в 30 дней.

Подробности: [авторизация и обновление токенов](https://developer.kontur.ru/doc/diadoc-api/authentication.html).

## Настройка CLI

Создай приватный env-файл вне репозитория, например `~/.config/diadoc/diadoc.env`, с правами `0600`:

```dotenv
DIADOC_CLIENT_ID=ID_ПРИЛОЖЕНИЯ
DIADOC_CLIENT_SECRET=API_КЛЮЧ_ПРИЛОЖЕНИЯ
DIADOC_REFRESH_TOKEN=REFRESH_TOKEN_ИЗ_КАБИНЕТА
```

Все три переменные обязательны при обращении к API. Указывай значения без префиксов. Готовый `DIADOC_ACCESS_TOKEN` больше не поддерживается. Не передавай секреты в чат.

Из каталога скилла выполни:

```bash
unset DIADOC_CLIENT_ID DIADOC_CLIENT_SECRET DIADOC_REFRESH_TOKEN
python3 scripts/diadoc.py --env-file ~/.config/diadoc/diadoc.env check
python3 scripts/diadoc.py --env-file ~/.config/diadoc/diadoc.env organizations
```

`check` возвращает `{"ok":true}` при доступе к списку организаций. В ответе `organizations` выбери нужную организацию и её `Boxes[].BoxId`; для документов передавай `--box-id` перед командой. Принимается GUID или BoxId с суффиксом `@diadoc.ru`. Проверка списка организаций не подтверждает права на все операции.

Окружение процесса имеет приоритет над файлом, даже если переменная пустая; `unset` в примере убирает это перекрытие. Без `--env-file` читается `.env` текущего каталога, если хотя бы одна из трёх переменных отсутствует в окружении. Явно указанный файл должен существовать. Формат — UTF-8, `KEY=VALUE`, допустимы кавычки и комментарии `#`; подстановки и команды не выполняются, `export` не поддерживается.

`draft-create --dry-run` работает локально без авторизации; `draft-copy --dry-run` получает токен для чтения источника.

Для службы настрой окружение или путь к файлу у запускающего процесса. Клиент работает с основной площадкой `https://diadoc-api.kontur.ru`.

## Ошибки

| Код | Что проверить |
|---|---|
| `credentials_required` | Все три переменные заданы и непустые; окружение не перекрывает файл. |
| `config_error` | Путь, права и синтаксис env-файла. |
| `authentication_failed` | ID и API-ключ приложения, режим авторизации, срок действия refresh token. |
| `invalid_response` | Сервер вернул некорректный ответ; токен не используется. |
| `network_error` | Доступность сети и сервиса авторизации; запрос не повторялся. |
| `token_expired` / 401 | Повтори безопасный `check`: новый процесс получит новый access token. |
| `subscription_required` / 402 | Подключение и оплату доступа к API. |
| `access_denied` / 403 | Права учётной записи и выбранный ящик. |

Успех: JSON в stdout, код `0`. Ошибка: JSON с `error.code` и `error.message` в stderr, код `1`. Автоматических повторов нет. При `operation_pending` или `write_outcome_unknown` следуй [правилам восстановления записи](documents.md#незавершённая-операция-и-повтор).
