# Авторизация

Документация проверена 15.10.2026. На production 19.10.2026 проверены сервисная авторизация, получение организаций, список входящих поступлений и чтение карточек. Запись и сервисный вход на тестовом хосте не проверены.

## Настройка CLI

Используется только сервисная авторизация приложения. Для каждого ключа CLI сначала читает переменную окружения; если она отсутствует — значение из `.env` текущего рабочего каталога. Пустая переменная окружения не заменяется значением из файла и приводит к `credentials_required` при обращении к API.

| Переменная | Назначение | Поле запроса API |
|---|---|---|
| `SBIS_APP_CLIENT_ID` | ID приложения | `app_client_id` |
| `SBIS_APP_SECRET` | Секрет приложения | `app_secret` |
| `SBIS_SECRET_KEY` | Сервисный ключ | `secret_key` |

Пример `.env` (заполни локально; не передавай секреты в чат):

```dotenv
SBIS_APP_CLIENT_ID=
SBIS_APP_SECRET=
SBIS_SECRET_KEY=
```

Окружение и `.env` можно сочетать: приоритет применяется отдельно к каждому ключу. CLI не меняет окружение процесса. Если все три переменные присутствуют в окружении, стандартный `.env` не читается. Отсутствующий стандартный файл допустим; недостающие или пустые обязательные значения блокируют сетевой запрос.

Глобальный аргумент `--env-file PATH` заменяет стандартный путь. Явно указанный файл читается даже при полном окружении; отсутствие файла, невозможность прочитать его или неверный синтаксис возвращают `config_error` без содержимого файла в диагностике.

Поддерживаются UTF-8, пустые строки, комментарии `#`, записи `KEY=VALUE`, пробелы вокруг `=` и значения в одинарных или двойных кавычках. Вне кавычек комментарий начинается с `#` в начале значения или после пробела; внутри кавычек `#` сохраняется. Значения однострочные и буквальные: команды, подстановки переменных и escape-последовательности не выполняются. Синтаксис `export KEY=VALUE` не поддерживается.

Примеры относительно каталога скилла (`.env` ищется в каталоге запуска):

```bash
python3 scripts/sbis.py check
python3 scripts/sbis.py --env-file /secure/sbis.env check
python3 scripts/sbis.py --profile test check
python3 scripts/sbis.py --timeout 120 organizations
python3 scripts/sbis.py --cache-dir /secure/sbis-cache check
```

Глобальные аргументы указываются перед командой. `check` вызывает `СБИС.СписокНашихОрганизаций` с пустым фильтром, возвращает только `ok` и профиль, без реквизитов организаций. Успех подтверждает доступ к этому методу, но не наличие организаций или права на остальные операции. `organizations` вызывает тот же метод и возвращает его результат, без автоматического обхода страниц. `СБИС.ИнформацияОТекущемПользователе` при живой проверке вернул HTTP 404 и для проверки доступа не используется. Профиль `test` — отдельный стенд, для него нужны собственные доступ и права.

## Контракт запросов

По [документации сервисной авторизации](https://link.sbis.ru/page/kbase_entity/3033991d-f3da-41b6-9b8b-4c719df25e5a?folderId=b232dc93-97c9-4133-b999-7ac34ee58229) клиент отправляет POST с тремя полями в JSON без обёртки JSON-RPC на `/oauth/service/`. Ответ должен содержать непустую строку `token`. В запросах ЭДО токен передаётся в `X-SBISAccessToken`; поля `access_token`, `sid` и заголовок `X-SBISSessionID` не используются.

| Профиль | Получение токена | Команды ЭДО |
|---|---|---|
| `production` | `https://online.sbis.ru/oauth/service/` | `https://online.sbis.ru/service/?srv=1` |
| `test` | `https://fix-online.sbis.ru/oauth/service/` | `https://fix-online.sbis.ru/service/?srv=1` |

Адреса ЭДО взяты из [технических требований](https://saby.ru/help/integration/api/techreq_edo). Адрес сервисного входа для `test` строится по хосту профиля и пока не подтверждён реальным запросом. Успешное получение токена само по себе не подтверждает доступность всех методов ЭДО: проверь `check` и доступные организации перед записью.

## Приватный кэш

Токен переиспользуется в памяти и сохраняется в `$XDG_CACHE_HOME/sbis/`, если `XDG_CACHE_HOME` задан абсолютным путём; иначе используется `~/.cache/sbis/`. Глобальный аргумент `--cache-dir PATH` задаёт сам каталог кэша и имеет приоритет над стандартным расположением. `XDG_CACHE_HOME` читается из окружения процесса, а не из `.env`. Имя файла — SHA-256 от версии формата, профиля и трёх параметров доступа. Каталог имеет права `0700`, файл — `0600`, замена атомарная. Исходные ключи в файл не записываются; смена любого ключа выбирает другую запись.

Кэш содержит действующий токен в открытом виде и должен оставаться приватным. Права рассчитаны на POSIX/Linux; на Windows дополнительно требуется ограничить ACL пользовательского каталога. При недоступном кэше клиент может продолжить работу с токеном в памяти и статическим предупреждением в stderr.

При HTTP 401 токен в памяти и соответствующий файл кэша сбрасываются; CLI возвращает `token_expired`. Автоматического повторения операции нет. Повтори безопасное чтение, чтобы получить новый токен. Перед повторной записью проверь состояние документа. Ошибки JSON-RPC с HTTP 200 также завершают команду без повторов и без анализа текста ошибки для выбора другого способа входа.

## Диагностика

Успех: JSON в stdout, код завершения `0`. Ошибка: JSON `{"error":{"code":"…","message":"…"}}` в stderr, код `1`; stdout пуст. `--help` выводит справку обычным текстом.

Основные коды: `credentials_required`, `config_error`, `token_expired`, `access_denied`, `rpc_error`, `http_error`, `network_error`, `invalid_response`. Секреты и токен маскируются в результатах; произвольные сообщения и трассировки сервера скрываются. CLI не принимает секреты аргументами командной строки и не печатает полученный токен.
