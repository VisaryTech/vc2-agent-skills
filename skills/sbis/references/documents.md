# Документы и команды CLI

Примеры выполняются из каталога скилла; JSON и выгрузки размещай вне репозитория. Дата проверки документации: 15.10.2026. На production 19.10.2026 проверены список входящих поступлений и чтение карточек. Скачивание вложений и запись проверены только автономно, с подменённым HTTP-транспортом.

## Поиск и состояние

Создай `/tmp/sbis-filter.json` с объектом фильтра без обёртки `Фильтр`:

```json
{
  "Тип": "ДокОтгрИсх",
  "Направление": "Исходящий",
  "ДатаС": "01.10.2026",
  "ДатаПо": "15.10.2026",
  "Навигация": {"РазмерСтраницы": "20", "Страница": "0"}
}
```

```bash
python3 scripts/sbis.py list --filter /tmp/sbis-filter.json
python3 scripts/sbis.py list --filter /tmp/sbis-filter.json --all
python3 scripts/sbis.py list --filter /tmp/sbis-filter.json --all --max-pages 500
python3 scripts/sbis.py read DOCUMENT_ID
python3 scripts/sbis.py download DOCUMENT_ID --output /tmp/sbis-export
python3 scripts/sbis.py download DOCUMENT_ID --archive --output /tmp/sbis-export
```

[`СБИС.СписокДокументов`](https://saby.ru/help/integration/api/all_methods/list_doc) требует `Тип`. Поддерживаются документированные фильтры: даты `ДД.ММ.ГГГГ`, направление, состояние, маска, организация, контрагент, регламент, подразделение, ответственный. CLI передаёт JSON-фильтр как есть, проверяет наличие типа и навигацию; доступность конкретных комбинаций определяет API. Размер страницы 1–200, нумерация с нуля. Без `--all` возвращается одна страница в исходном формате; с `--all` объединяются `Документ`, возвращаются последняя `Навигация` и `all_pages: true`. Не считай постраничное чтение моментальным снимком изменяющихся данных.

С `--all` действует лимит `--max-pages N` — положительное целое число, по умолчанию 10000 запросов страниц. Он считается от начальной страницы фильтра, независимо от её номера. Если после последнего разрешённого запроса остаются страницы, CLI возвращает `pagination_limit` без частичного результата. Увеличь лимит или сузь фильтр и повтори чтение. Если последняя страница получена ровно на границе лимита, операция завершается успешно. Без `--all` читается одна страница.

[`СБИС.ПрочитатьДокумент`](https://saby.ru/help/integration/api/all_methods/read_doc) возвращает карточку с `Состояние.Код`, `Состояние.Название`, редакциями, вложениями и ссылками. CLI допускает как прямой объект результата, так и обёртку `Документ`. Статусы не сводятся к булевому «подписан»: используй [официальные коды](https://saby.ru/help/integration/api/sequence/cod/), например `0` — редактируется, `3` — отправлен, `4` — доставлен, `7` — выполнение завершено успешно.

`download` читает карточку заново, сохраняет её вложения и доступные подписи последовательными GET-запросами. ZIP не распаковывается, имена очищаются от компонентов пути, существующие файлы не перезаписываются, при совпадении добавляется суффикс. Файлы создаются с правами `0600`; выгруженные данные могут быть конфиденциальными.

`download --archive` — альтернативная выгрузка всех вложений и ЭП одним ZIP: читает карточку заново и выполняет GET по `Документ.СсылкаНаАрхив`, без отдельных запросов файлов. Это поле документа, а не отдельный метод JSON-RPC. Архив сохраняется без распаковки под безопасным именем `DOCUMENT_ID.zip`, с теми же правами и защитой от перезаписи. Результат: `{"document_id": "DOCUMENT_ID", "files": [{"kind": "archive", "path": "/tmp/sbis-export/DOCUMENT_ID.zip", "bytes": 123}]}`. См. [выгрузку полного архива](https://saby.ru/help/integration/api/sequence/loc_arh).

Если ссылка отсутствует, команда возвращает `archive_unavailable`. При структурированном ответе с кодом `00000000-0000-0000-0000-1AA0000F1002`, в том числе в теле HTTP-ошибки, возвращается `archive_not_ready`: повтори команду через 5–10 секунд. Сервер [готовит архив асинхронно](https://saby.ru/help/integration/api/history); автоматических повторов нет. Вместо ZIP файл ошибки не сохраняется; прочий ответ без ZIP отклоняется как `invalid_response`, HTTP-ошибки сохраняют обычную диагностику доступа/HTTP. Лимит клиента 60 МиБ применяется ко всему ZIP. Обычный `download` не переключается на архив автоматически. Контракт архива проверен по документации 26.10.2026; проверка реализации — автономная, без production.

Ссылки принимаются только по HTTPS на `sbis.ru`/`saby.ru` и их поддомены; правило проверяется и при перенаправлениях. Заголовок токена к скачиваниям не добавляется. Это рассчитано на ссылки, возвращаемые API; при необходимости иной схемы доступа потребуется отдельно подтвердить её контракт. При HTTP 403 заново прочитай документ для обновления ссылки, затем проверь права. Ссылки имеют ограниченный срок действия. Если возвращено `ЧастичныеДанные: "Да"`, `read` показывает этот признак, а полная выгрузка и обновление блокируются. Автоматическое дополнение через `СБИС.СписокИзменений` в v1 отсутствует.

## Создание черновика

Вход — объект `Документ` без внешней обёртки и без идентификатора. Тип указывай явно. Перед записью заполни данные реальных отправителя и контрагента. Следующий пример требует замены значений в угловых скобках:

```json
{
  "Тип": "ДокОтгрИсх",
  "Номер": "Тест-1",
  "Дата": "15.10.2026",
  "Примечание": "Черновик для проверки интеграции",
  "НашаОрганизация": {"СвЮЛ": {"ИНН": "<ИНН отправителя>", "КПП": "<КПП отправителя>"}},
  "Контрагент": {"СвЮЛ": {"ИНН": "<ИНН получателя>", "КПП": "<КПП получателя>"}}
}
```

Сохрани заполненный объект в `/tmp/sbis-draft.json` и используй существующий файл вложения:

```bash
python3 scripts/sbis.py draft-create --input /tmp/sbis-draft.json --attachment /tmp/document.pdf --dry-run
python3 scripts/sbis.py draft-create --input /tmp/sbis-draft.json --attachment /tmp/document.pdf
```

`--input -` читает JSON из stdin. `--attachment PATH` можно повторять. CLI кодирует файлы в Base64. Неформализованные PDF и прочие файлы загружаются как есть; формализованные XML должны уже соответствовать формату — генерация УПД не входит в v1. Идентификатор и предупреждения созданного документа берутся из фактического результата API. Черновик может быть создан с зафиксированной в нём ошибкой: успешный HTTP-вызов не означает готовности к отправке.

## Обновление и сохранение вложений

В `/tmp/sbis-patch.json` передай только изменяемые реквизиты, например `{"Примечание":"Обновлённый комментарий"}`:

```bash
python3 scripts/sbis.py draft-update DOCUMENT_ID --input /tmp/sbis-patch.json --dry-run
python3 scripts/sbis.py draft-update DOCUMENT_ID --input /tmp/sbis-patch.json
python3 scripts/sbis.py draft-update DOCUMENT_ID --input /tmp/sbis-patch.json --replace-attachment ATTACHMENT_ID=/tmp/new.pdf --dry-run
python3 scripts/sbis.py draft-update DOCUMENT_ID --input /tmp/sbis-patch.json --remove-attachment ATTACHMENT_ID --dry-run
```

Клиент требует направление `Исходящий`, код состояния `0`, отсутствие признаков удаления и частичных данных. Перед обновлением он запрашивает `ДопПоля: "Расширение"` и допускает запись только при явном `Расширение.ЗакрытОтИзменений: "Нет"`. Значение `Да`, неизвестное значение или отсутствие признака блокируют обновление с `not_draft`; неизвестное состояние документа также приводит к отказу. Обычный `read` дополнительных полей не требует. Реквизиты из разрешённого набора объединяются с текущими данными; служебные поля состояния и этапов не отправляются. Существующие вложения и подписи загружаются и передаются заново с поддерживаемыми реквизитами `Сертификат.Доверенность`: [`СБИС.ЗаписатьДокумент`](https://saby.ru/help/integration/api/all_methods/doc) может удалить прежние вложения при перезаписи черновика. Другие поля сертификата из ответа чтения не передаются.

- `--attachment` добавляет файл.
- `--replace-attachment ID=PATH` заменяет файл, удаляя недействительные подписи старого содержимого из подготовленного запроса.
- `--remove-attachment ID` явно исключает вложение.
- Входной `Вложение` объединяется по идентификаторам; элементы без ID добавляются. Пустой массив не удаляет существующие файлы. Для нового или заменяемого файла допускаются `Файл.Имя` и `Файл.ДвоичныеДанные` либо временная `Файл.Ссылка` СБИС. Новые подписи через входной JSON не принимаются.

`--dry-run` возвращает метод и подготовленные параметры; вместо Base64 показывает число символов. Этот JSON предназначен для просмотра и не является готовым запросом для повторного исполнения.

Непосредственно перед обновлением клиент повторно читает документ с `ДопПоля: "Расширение"`, проверяет явное разрешение изменений и сравнивает его с первоначальным ответом. Если разрешение больше не подтверждено, запись блокируется с `not_draft`; при остальных отличиях — с `document_changed`. Это может потребовать нового предпросмотра и при изменении временных ссылок сервера. Не редактируй документ одновременно в интерфейсе СБИС и через CLI. API чтения и записи не предоставляет здесь подтверждённой атомарной блокировки: повторная проверка не является транзакцией с сервером.

## Лимиты и неопределённая запись

CLI использует последовательные запросы, без автоматических повторов. Предельный размер JSON-запроса — 100 МиБ, число вложений — 10. Для одного скачиваемого или загружаемого файла принят консервативный предел 60 МиБ: [технические требования](https://saby.ru/help/integration/api/techreq_edo) и [описание объекта](https://saby.ru/help/integration/api/all_methods/object/) указывают разные границы. Base64 увеличивает итоговый JSON; даже файлы в пределах индивидуального лимита могут превысить лимит запроса.

`write_outcome_unknown` означает, что сервер мог выполнить запись до разрыва соединения, таймаута, HTTP 5xx или повреждения ответа. Не повторяй запись автоматически. Для обновления прочитай документ и сравни данные; для создания найди черновик по организации, типу, дате и номеру и проверь содержимое. Универсальной гарантии идемпотентности создания нет.

## Проверки

```bash
python3 -m unittest discover -s skills/sbis/tests -v
```

Команда запускается из корня репозитория. Для живой проверки после настройки доступа: `check`, `organizations`, ограниченный `list`, `read`, `download`; затем `draft-create --dry-run`, создание согласованного тестового черновика, его чтение, `draft-update --dry-run`, обновление и повторное чтение. Тестовый черновик не отправлять. Удаление после проверки выполняется отдельно в СБИС, если пользователь этого хочет.
